1# FreeToken test suite
2
3Directories mirror the `python/freetoken/` subsystem a test primarily exercises —
4put a new test next to the module it protects. There is no per-model directory:
5a model-specific test lives in the subsystem it stresses, and says which model
6in its filename (`kvcache/test_dsv4_pool.py`, `models/test_glm4_nvfp4.py`).
7
8| directory | subsystem under test |
9|--------------|----------------------|
10| `daemon/` | `freetoken.daemon` — torch-free supervisor (import safety, serve manager) |
11| `server/` | `freetoken.server` — OpenAI/Anthropic/Responses APIs, streaming, parsers, accounting, maintenance state |
12| `scheduler/` | `freetoken.scheduler` — chunked prefill, cache manager, commit/window locking, status reporting, KV usage, cost accounting |
13| `kvcache/` | `freetoken.kvcache` — paged pools (incl. DSV4's), rebuild, cache-cost accounting; the three prefix caches live in `kvcache/radix/` behind a shared reference model (see its README) |
14| `tokenizer/` | `freetoken.tokenizer` — tokenize/detokenize request plumbing, thinking-mode resolution |
15| `engine/` | `freetoken.engine` — cache budget planning, config resolution, backend gating |
16| `kernels/` | `freetoken.kernel` / `freetoken.layers` — attention, rope, fused ops, JIT cache, pinned memory |
17| `moe/` | `freetoken.moe` — offload cache, CPU/GPU expert kernels, quantized backends (fp8/nvfp4/mxfp4/gguf) |
18| `models/` | `freetoken.models` — the registry, and the loading machinery every model shares (sharding, qkv/expert merge, streaming layers into banks) |
19| `e2e/` | real-server gates: AIME 24/25/26 generation, runtime cache rebuild |
20
21The CLI surface itself is not unit-tested. `ft` dispatch, `ft ctl`, `ft launch` and
22`install.sh` are thin, they change often, and a test written after the fact only
23restates whatever the code currently does — running the command is the real gate.
24What does live here is the logic reachable *through* those commands when it has its
25own failure mode: `server/test_parser_auto_selection.py` covers the architecture ->
26parser inference behind `--tool-call-parser auto`.
27
28## Running
29
30```bash
31uv run pytest tests/ # full suite, ~2-4 min on a GPU box
32uv run pytest tests/ -m "not slow" # skip the handful of tens-of-seconds tests
33uv run pytest tests/kvcache/ # one subsystem
34```
35
36GPU-dependent tests skip themselves when CUDA is unavailable. Marlin NVFP4 tests
37skip unless `vllm` is importable (dedicated venv with `vllm>=0.14,<0.15`).

69`test_aime.py` takes its sampling protocol from the checkpoint's own
70`generation_config.json` (pass@N at the recommended temperature, or a single greedy
71sample when the checkpoint recommends greedy). To run an fp8 / offload checkpoint,
72point `FREETOKEN_TEST_MODEL` at the fp8 dir and set `FREETOKEN_TEST_MOE_CACHE_SIZE=8192`;
73`FREETOKEN_AIME_REQ=2 FREETOKEN_AIME_MAX_TOKENS=32768` is the offload recipe (req 2 with
74a 32k budget).
75
76Budget the token allowance for sampling, not for greedy: on Qwen3.5-35B-A3B-FP8 the three
77recommended-sampling samples of aime25 req 1 ran 4.1k / 10.7k / 10.0k tokens against greedy's
78~4k, and req 2 needs ~21k even greedy — hence the 32k budget for the harder problems.
79
80Run these before opening a PR — they are cheap, and a gate nobody trips rots silently:
81
82```bash
83FREETOKEN_REBUILD_TEST_MODEL=<small model dir> uv run pytest tests/e2e/test_cache_rebuild.py
84```

86## What earns a place here
87
88A test must be able to fail on a plausible regression of production code.
89
90Weigh that against how the bug would be found otherwise. Application-facing
91surfaces — the terminal UI, the access-log filter, the request ring, the status
92and health endpoints, the CLI — announce their own breakage the moment anyone
93uses them, and they change shape often enough that a unit test mostly restates
94today's implementation. Those belong to `e2e/` and to actually running the
95thing. What earns a unit test is logic that fails *silently*: a wrong number
96that still looks like a number, a model family that quietly stops having its
97tool calls parsed, a cache that returns the wrong slot. Prefer covering that
98where it lives rather than through the surface that happens to expose it.
99
100Writing a test in the same commit as the feature is right; what matters is where
101its expectations come from. A test that checks the result against something
102independent — a PyTorch reference, a round-trip, a CPU mirror, a live registry —
103keeps working when the implementation is rewritten, and can disagree with it.
104A test whose assertions restate the branch structure the author just wrote can
105only ever agree, so it never fails on anything except a deliberate change, and
106then it is edited to match. If you cannot name what the expectation is checked
107*against*, the test is unlikely to earn its place.
108Bug-repro tests should drive the current call pattern of the fixed code, not the
109pre-fix one; wire-format and kernel tests should assert against an independent
110reference (round-trip, dequant oracle, CPU mirror), not against the
111implementation's own output. Registry-style tests should iterate the live
112registry rather than hand-maintained whitelists, so new entries are covered
113automatically.
