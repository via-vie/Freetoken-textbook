40## MoE strategies
41
42`ft serve --moe-strategy {auto,fused,offload,cpu,hybrid}` (`--moe-backend` is the deprecated old spelling):
43
44- **fused** — experts resident on GPU (needs the VRAM). Serves every expert
45 format except DeepSeek-V4's.
46- **offload** — experts live in host RAM, an LRU cache of expert slots on GPU;
47 misses stream over PCIe.
48- **cpu** — misses are computed on the CPU instead of fetched.
49- **hybrid** — per step, fetches some misses over PCIe and computes the rest on
50 CPU, overlapped. Run `ft bench bw --model <checkpoint>` once per machine and
51 model to calibrate the split.
52- **auto** — dense models always resolve to `fused`; MoE models resolve to
53 `offload`. Unified-memory GPUs differ, see below.
54
55### Unified-memory GPUs (GB10 / DGX Spark)
56
57The GPU and the CPU share one DRAM, so offload only copies experts between two
58names for the same memory. On these GPUs `auto` resolves every MoE model to
59`fused`: the default is the resident path only. DeepSeek-V4 experts
60have no resident path and stay on `offload`. Offload-only flags
61(`--moe-cpu-layers`, `--moe-cache-size` / `-rate` / `-auto`,
62`--moe-prefill-hit-d2d`, `--disable-moe-prefill-overlap`) are ignored with a
63warning; pass `--moe-strategy offload` to use them.
64
65### NVLink-C2C hosts (GH200 / GB200)
66
67The host link is ~450 GB/s per direction instead of PCIe's ~32-64 GB/s. The
68offload expert gather reads host memory zero-copy and is latency-bound, so it
69needs a wider grid to keep enough loads in flight. Set
70`FREETOKEN_H2D_BLOCKS_PER_BANK`:
71```
72 FREETOKEN_H2D_BLOCKS_PER_BANK=32 ft serve --model <model> --moe-strategy offload
73```
74On GH200 this raises the gather from ~220 to ~410 GB/s (`PCIe-gather` in
75`ft bench bw`), matching the DMA ceiling. Run `ft bench bw` with the variable
76set so the hybrid split is calibrated against the faster gather. Leave it
77unset on PCIe GPUs: wider grids add no bandwidth there.

79## Notes
80
81- `ft checkpoint` conversion is optional — it pre-converts a checkpoint into
82 FreeToken's fast-load format, and `ft serve --model` auto-detects the result.
83- An FTW converted by an older build with `--moe-backend fused` or `triton` keeps
84 its experts as dense weights and no longer loads; reconvert it with `ft checkpoint`.
85- FTW files converted by builds before the quantization refactor may fail to load;
86 see [ftw-hotfix.md](ftw-hotfix.md) for the affected checkpoints and the repair tool.
87- An FTW converted before its family served images holds no vision encoder: `ft serve`
88 refuses it unless started with `--text-model-only` (or `--mm-disable vision`); reconvert it
89 with `ft checkpoint`, or add the encoder in place with [scripts/ftw_hotfix.py](ftw-hotfix.md).
90- DeepSeek-V4 checkpoints must keep the `inference/config.json` subdir — the
91 authoritative model args are read from there.
92- DeepSeek-V4.1-Flash serves text and images from the HF checkpoint as shipped (fp8 block-32
93 dense weights, fp4 experts on the offload cache, 890 B/token global KV in packed
94 fp4/fp8 pools). Its two 98 GiB Engram tables stream from the checkpoint shards on
95 demand (keep them on a fast NVMe; the 6 GiB of table scales stay in host RAM), using
96 bounded pinned staging buffers; an FTW conversion copies the shards that hold them next
97 to the checkpoint.
98 SWA bounded replay (DeepSeek_V41_Tech_Report.pdf, shipped in the checkpoint, §3.2.2): a replayed
99 segment recomputes only the SWA KV of its last `n_win` tokens and truncates each query's window to
100 the segment. *Encoder* replay rebuilds the encoder SWA KV behind a prefix hit from the global KV
101 alone (approximate; the report's fallback when the SWA KV of a hit has been evicted). *Decoder*
102 replay runs the decoder layers on each prompt's last `n_win` tokens only; their SWA KV is never
103 prefix-cached and post-training simulated it. FreeToken keeps encoder SWA KV in the radix cache (no
104 encoder replay); `--swa-decoder-replay bounded` (default) is the report's decoder replay, with a
105 prefix hit stopping at least `n_win` tokens before the prompt end so those tokens are prefilled;
106 `exact` runs the decoder on every prompt token (reference numerics).
107 Bounded output differs from exact by construction and does not depend on the prefill chunk size.
108 Under expert offload the prefill time is bounded by streaming each layer's experts, so decoder
109 replay saves decoder-layer compute, not prefill time.
110 Run `ft bench bw --model <checkpoint>` to measure local PCIe and CPU bandwidth before
111 choosing a MoE strategy; `--moe-strategy hybrid` splits expert misses using those
112 measurements. With `--moe-cache-auto`, `--kv-reserve-tokens` sets the token capacity reserved
113 before the expert cache is allocated, subject to the attention pool's structural minimum; size it
114 for the intended context and concurrency. `--max-extend-length` controls the prefill chunk size
115 and its workspace. Image input uses the shared multimodal processor and encoder cache, including
116 chunked prefill and prefix replay; `--text-model-only` skips the vision weights. DSpark
117 speculative decoding is not served.
118 `reasoning_effort` takes `low`, `high` or `max`; the 1-100 integer budget goes through the
119 template kwargs with thinking on, `"chat_template_kwargs": {"enable_thinking": true,
120 "reasoning_effort": 37}`, and the checkpoint's encoder validates it. Runtime window-cache
121 controls use 128-token pages.
122- Qwen3.8-Flash-Next keeps a 47.7 GiB PLE n-gram table pinned in host RAM.
