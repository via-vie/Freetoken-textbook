1# CLI reference
2
3```
4ft <command> [args]
5```
6
7| Command | Purpose |
8|---|---|
9| `ft serve` | Start the API server (OpenAI `/v1/*`, Anthropic `/v1/messages`, Responses) |
10| `ft shell` | Chat with a server in the terminal |
11| `ft ctl` | Query and manage a running server over HTTP |
12| `ft launch` | Configure and launch a coding agent against a server |
13| `ft checkpoint` | Convert an HF checkpoint to the FTW fast-load format |
14| `ft bench bw` | Benchmark CPU vs PCIe bandwidth to calibrate hybrid MoE decode |
15
16`ft --version` prints the installed version (torch-free; nightly wheels carry a
17`+g<sha>` build stamp, tagged releases a bare version). Every command supports
18`--help`.
19
20## ft serve
21
22```bash
23ft serve --model <path-or-hf-id> [options]
24```
25
26`--model` is the only required flag — dtype, attention backend, MoE backend,
27MoE cache size, KV capacity, CUDA-graph sizes and the tool-call/reasoning
28parsers all resolve automatically from the checkpoint and the GPU.
29
30### Model
31
32| Flag | Default | Meaning |
33|---|---|---|
34| `--model-path`, `--model` | required | Local dir, HF repo id, or an FTW dir (auto-detected) |
35| `--served-model-name` | basename of `--model` | Model id reported by `/v1/models` |
36| `--hf-overrides` | — | JSON object applied to the checkpoint's config as vLLM's `--hf-overrides`: a nested config section updates key by key, any other value is replaced whole. A YaRN `rope_parameters` override serves `original_max_position_embeddings * factor` positions |
37
38### Server & runtime
39
40| Flag | Default | Meaning |
41|---|---|---|
42| `--host` | 127.0.0.1 | Bind address |
43| `--port` | 1919 | Bind port |
44| `--api-key` | `$FREETOKEN_API_KEY`, else off | Require the key on every route except `/health`, as `Authorization: Bearer <key>` or `x-api-key: <key>`; other requests get a 401 |
45| `--gpu` | GPU 0 | GPU to run on: a UUID from `nvidia-smi -L` or an `nvidia-smi` index; see [below](#choosing-a-gpu) |
46| `--max-running-requests` | 4 | Max concurrently running requests |
47| `--max-output-tokens` | 32768 | Default output budget for requests that omit one |
48| `--max-seq-len-override` | from checkpoint | Max sequence length |
49| `--max-prefill-length` | 8192 | Chunked-prefill chunk size in tokens |
50| `--cuda-graph-max-bs`, `--graph` | = max running requests | Max batch size captured as CUDA graphs |
51| `--decode-log-interval` | 40 | Scheduler status line every N decode steps |

53### Choosing a GPU
54
55For example, a machine with an RTX 5090 and an RTX 3060 Ti:
56
57```console
58$ nvidia-smi -L
59GPU 0: NVIDIA GeForce RTX 3060 Ti (UUID: GPU-2f3a9b1c-8d7e-4a05-b6c1-0e5f9a3d7b42)
60GPU 1: NVIDIA GeForce RTX 5090 (UUID: GPU-9e8d7c6b-5a49-4f13-8207-c1b0a4e6d3f5)
61```
62
63```bash
64ft serve --model ... --gpu 1 # by nvidia-smi index -- the 5090
65ft serve --model ... --gpu GPU-9e8d7c6b # the same card by UUID (a unique prefix is enough)
66```

68### KV cache & memory
69
70| Flag | Default | Meaning |
71|---|---|---|
72| `--memory-ratio` | 0.9 | Fraction of free VRAM the engine may use (weights + MoE cache + KV) |
73| `--num-pages` / `--num-tokens` | auto | KV capacity override in pages / tokens (mutually exclusive; auto sizes from VRAM left after weights and MoE cache) |
74| `--page-size` | 1 | KV page size; DSV4 forces 128, the TRTLLM backend needs 16/32/64, SWA models require 1 |
75| `--cache-type` | radix | `radix` (prefix reuse; SWA/GDN-aware variants picked automatically) or `naive` |
76| `--attention-backend`, `--attn` | auto | `trtllm`/`fi`/`fa`/`triton`/`dsv4_sparse`/`dsa`; `prefill,decode` pair allowed; auto picks per model + GPU |

78### MoE offload
79
80See [models.md](models.md#moe-strategies) for what each strategy does.
81
82| Flag | Default | Meaning |
83|---|---|---|
84| `--moe-strategy` | auto | `fused`/`offload`/`cpu`/`hybrid`; auto → offload; fused on unified-memory GPUs (GB10), see [models.md](models.md#unified-memory-gpus-gb10--dgx-spark). `--moe-backend` is the deprecated old spelling |
85| `--quant-backend` | auto | Kernel per quantized layer type, `layer[.kind]=name` entries: `linear=marlin,moe=b12x` or `moe.nvfp4=triton`. A layer-level entry applies to every kind whose table lists the name |
86| `--nvfp4-backend` | — | Deprecated: stands in for `--quant-backend moe.nvfp4=<marlin\|b12x\|triton>` (`flashinfer` means b12x); cannot be combined with `--quant-backend` |
87| `--moe-cache-size` / `--moe-cache-rate` / `--moe-cache-mem` / `--moe-cache-auto` | auto | GPU expert-cache size as slots / fraction of all experts / memory such as `12GiB` / sized from free VRAM (mutually exclusive; auto is enabled by default for offload-family strategies) |
88| `--moe-cache-scope` | unified | `unified`: one LRU pool of slots per expert quant (quant type and bank layout), so all MoE layers share one pool when they share a quant format; `per-layer`: each layer has its own pool. `per-layer` does not combine with `--moe-strategy cpu` or `--moe-cpu-layers` |
89| `--moe-cache-split` | equal | How the pools share the slots: `equal` (in proportion to their layer counts), or `profile:<path>`: every pool keeps `top_k` slots and the rest go to the most used experts in the profile's per-layer expert counts. With `offload`, a pool smaller than the expert count lowers `--max-running-requests` to its slots / top_k |
90| `--kv-reserve-tokens` | 8192 | KV token floor reserved before `--moe-cache-auto` fills experts |
91| `--moe-cpu-threads` | physical cores | CPU worker threads for the cpu/hybrid executor |
92| `--moe-cpu-layers` | all on GPU | With `offload`: which MoE layers decode on CPU (`3,7,11`, a count, a fraction, or `auto`). `auto` is for Windows/WSL only, where CUDA pinned memory is capped; every value needs an expert format the CPU executor serves (bf16, fp8_block, nvfp4, mxfp4, GGUF on x86 CPUs) |
93| `--moe-hybrid-max-fetch` | auto | With `hybrid`: max experts fetched over PCIe per layer per step; rest computed on CPU |
94| `--moe-prefill-hit-d2d` | off | Prefill: copy cache-hit experts device-side, stream only misses (CUDA >= 13) |
95| `--disable-moe-prefill-overlap` | overlap on | Disable the two-buffer prefill copy overlap |

107### Image input
108
109Experimental. Needs a checkpoint whose family registers a vision encoder ([models.md](models.md#image-input) lists them and how each one
110maps the flags below); a request carrying images is rejected otherwise. Images are accepted on all three protocols (OpenAI `image_url`,
111Anthropic `image` blocks, Responses `input_image`) as an http(s) URL or base64. Images inside a tool
112result (an Anthropic `tool_result` block from Claude Code's Read, a Responses `function_call_output`
113from Codex's view_image) are moved to the user turn that follows the tool message, as vLLM does,
114because chat templates render tool messages as plain text.
115`GET /v1/stats` reports what the server accepts as `model.input_modalities` (`["text"]` or `["text", "image"]`),
116so a client can gate its attachment controls without reading the checkpoint config.
117
118| Flag | Default | Meaning |
119| --- | --- | --- |
120| `--text-model-only` | off | Serve a multimodal checkpoint text-only: no encoder tower is built (its VRAM goes to the KV/expert pools) and every multimodal input is rejected. Same as `--mm-disable` with every encoder kind |
121| `--mm-disable` | none | Encoder towers to leave unbuilt (`vision`, `audio`); every input they would serve is rejected |
122| `--mm-encoder-weights` | host | Where the encoder tower's block weights live. `host` streams them from pinned host banks two blocks at a time behind the compute, so the GPU holds two blocks instead of the whole tower; small images pay the copy time, large ones hide it behind the compute. `gpu` keeps them resident. An encoder without a block stack stays resident either way |
123| `--image-min-tokens`, `--image-max-tokens` | processor defaults | Per-image token budget: the image processor resizes every image to take between these many tokens, converted to the family's own units by its processor. A family with fixed budgets honors the maximum only and refuses one below its smallest budget at start-up |
124| `--mm-processor-kwargs` | none | JSON object of extra keyword arguments for the checkpoint's image processor call, for knobs the token budget does not cover; applied after the budget, so an explicit key wins |
125| `--mm-embed-cache-device` | cpu | Where encoded image embeddings live between prefill chunks. `cpu` keeps them out of the VRAM budget; `cuda` skips the copy back |
126| `--allowed-media-domains` | any | Comma-separated hostname allowlist for image URLs; requests for other domains are rejected with a 400. Empty allows any domain |
127| `--allowed-local-media-path` | off | Directory `file://` image refs may be read from; unset rejects local files |

129## ft shell
130
131```bash
132ft shell # attach to a running server
133ft shell --model ~/models/Qwen3.6-35B-A3B # serve + chat in one process
134```
135
136- Attach mode talks to `--server URL` (default `http://127.0.0.1:1919`)
137- `--api-key KEY` (default `$FREETOKEN_API_KEY`) attaches to a server started with `--api-key`; with `--model` the shell uses that server's own key
138- `/help` inside the shell lists the commands (`/think`, `/cache`, `/reset`).

140## ft ctl
141
142```bash
143ft ctl [--base-url http://127.0.0.1:1919] [--api-key KEY] [--timeout 10] [--json] <subcommand>
144```
145
146`--api-key` defaults to `$FREETOKEN_API_KEY`.
147
148| Subcommand | Endpoint | Purpose |
149|---|---|---|
150| `health` | `GET /health` | Server status, model, load progress |
151| `stats` | `GET /v1/stats` | Throughput, latency, VRAM, pool occupancy, accepted input modalities |
152| `generate [prompt] [--max-tokens N] [--ignore-eos]` | `POST /generate` | Raw completion smoke test (no chat template) |
153| `cache` | `GET /v1/cache/status` | Cache pool table |
154| `cache --moe N \| --kv N \| --mamba N \| --swa N [--wait 300]` | `POST /v1/cache/rebuild` | Live pool resizing without a restart (`k`/`m` suffixes; `--kv`/`--swa` in tokens) |
155| `requests [--since N] [--limit N]` | `GET /v1/requests` | Recent request ring |

157## ft launch
158
159```bash
160ft launch {claude,codex,dsh,hermes,openclaw,opencode} [options] [-- <agent args>]
161```
162
163Discovers the served model via `/v1/models`, writes the agent's provider
164config, installs the agent CLI if missing, then launches it. Cloud API keys
165(`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, …) are cleared from the child
166environment so the agent cannot silently fall back to a paid endpoint.
167When `/v1/stats` reports `image` among `model.input_modalities`, the written
168config declares the model image-capable, which Codex, OpenCode, OpenClaw and
169dsh require before their image tools and attachments send anything; Claude
170Code and Hermes need no declaration.
171
172| Flag | Meaning |
173|---|---|
174| `--server URL` | Server to point the agent at (default `http://127.0.0.1:1919`) |
175| `--api-key KEY` | Key of a server started with `--api-key` (default `$FREETOKEN_API_KEY`). The agent gets it in its environment; Hermes and OpenClaw keep it in their config files |
176| `--dry-run` | Print the planned config changes and command, touch nothing |
177| `-y`, `--yes` | Approve install/config prompts |
178| `--config` | Configure without launching |
179| `--install-only` | Just install the agent CLI (needs no server) |
180| `--force-reinstall` | Re-run the agent installer |
181| `-- <args>` | Forwarded verbatim to the agent |

183## ft checkpoint
184
185```bash
186ft checkpoint --model <hf_dir> --out <ftw_dir> [--dtype bfloat16] [--moe-backend offload] [--quant-backend moe.nvfp4=b12x] [--shard-gib 8] [--gpu <uuid-or-index>]
187```
188
189Converts an HF safetensors checkpoint to FTW, FreeToken's self-contained
190fast-load format; point `ft serve --model` at the output dir. MoE experts are
191always packed into expert banks, which serve the fused and the offload
192strategies alike (DeepSeek-V4 experts serve offload only);
193`--moe-backend` is kept for compatibility. See the FTW caveats in
194[models.md](models.md#notes); FTW files from older builds can be repaired with
195[scripts/ftw_hotfix.py](ftw-hotfix.md) instead of reconverting.
196
197## ft bench bw
198
199```bash
200ft bench bw --model /path/to/model.gguf # every MoE layer kind of a checkpoint (GGUF or HF)
201ft bench bw # canonical geometry per expert format
202ft bench bw --gpu 1 # a specific GPU (UUID or nvidia-smi index, as for ft serve)
203```
204
205Measures host-RAM vs PCIe bandwidth with the real cpu/offload MoE kernels and writes one
206row per MoE layer kind, which `ft serve --moe-strategy hybrid --moe-hybrid-max-fetch -1` reads
207to split each layer's misses.
208
209- One profile per GPU, at `~/.cache/freetoken/benchbw/<gpu-uuid>.json`; a profile from other
210 hardware or another profile version is ignored.
211- A row's key is the layer's CPU format and options, expert shape, top_k and CPU worker
212 threads; a layer without an exact row keeps a fetch cap of 1. Bench with the same
213 `--cpu-threads` as the server's `--moe-cpu-threads`.
214- Each run replaces the rows it benched and keeps the others.
215- What to measure: `--model` (checkpoint paths or presets), `--dtype`, `--formats`, `--isa`.
216- `--threshold` (default 2.0) sets each row's `recommended`: hybrid when CPU bandwidth beats
217 PCIe by that factor.
218
219On NVLink-C2C hosts, see [models.md](models.md#nvlink-c2c-hosts-gh200--gb200)
220for `FREETOKEN_H2D_BLOCKS_PER_BANK` if `PCIe-gather` sits well below the linear H2D ceiling.
